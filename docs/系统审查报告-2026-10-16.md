# go购够商城（scDemo-front）系统审查报告

- **审查日期**：2026-10-16
- **审查范围**：前端代码（`src/` 目录）、路由与权限、认证与会话、订单支付链路、上传与富文本、依赖配置
- **说明**：结论基于前端代码可见证据，后端接口权限、数据库约束和部署配置仍需联调验证；本次审查未修改任何业务代码，`npm run lint` 通过。

## 一、系统整改建议（10 条）

1. **完善后端权限校验**
   前端路由权限只能改善体验，。不能作为安全边界订单、用户、地址、售后、商品、支付等接口必须后端校验当前用户身份、角色和数据归属。

2. **修复订单越权风险**
   所有 `/order/{id}`、取消订单、删除订单、发货、售后、支付等接口，必须校验订单所属用户或商家经营范围，避免通过修改订单 ID 查看或操作他人数据。

3. **改进 Token 存储机制**
   当前 Token 存在 `localStorage`，存在 XSS 窃取风险。建议改为短期 Access Token + HttpOnly、Secure、SameSite Cookie，并配合刷新 Token 和主动注销机制。

4. **统一输入校验和输出编码**
   商品名称、公告内容、知识库、售后原因、客服内容等必须服务端校验长度、格式和危险标签。富文本输出建议统一使用可信 HTML 白名单过滤。

5. **加强文件上传安全**
   不能只依赖前端 MIME 类型和扩展名校验。后端应校验真实文件类型、大小、分辨率和内容，重命名存储，禁止脚本执行，并使用独立静态资源域名。

6. **支付流程改为真实状态机**
   支付金额、优惠券、商品价格、库存必须以后端实时计算为准。支付成功只能由可信支付回调确认，前端轮询结果不能直接改变订单状态。

7. **完善验证码和密码找回机制**
   短信/邮箱验证码接口增加 IP、手机号、设备、账号维度限流；验证码服务端一次性消费、短时有效、失败次数限制，密码重置后使旧 Token 全部失效。

8. **增加并发控制和幂等机制**
   下单、支付、取消订单、售后申请、优惠券领取、秒杀接口应增加幂等键、数据库唯一约束、库存原子扣减和重复请求保护。

9. **补充安全响应头和传输安全**
   生产环境强制 HTTPS，并配置 CSP、X-Content-Type-Options、Referrer-Policy、Permissions-Policy、HSTS 等响应头。

10. **建立可观测性和审计体系**
    对登录失败、密码重置、支付、退款、发货、权限变更、用户资料修改、文件上传记录审计日志，并增加异常告警和操作追踪 ID。

## 二、新功能建议（10 条）

1. **购物车价格和库存实时提醒**：商品涨价、降价、库存不足、失效时主动提示。
2. **订单拆单与多商家配送**：支持不同商家商品拆分订单、分别支付和跟踪物流。
3. **真实优惠券中心**：支持满减券、折扣券、品类券、商家券、使用规则和自动推荐。
4. **物流轨迹查询**：接入物流平台，展示物流节点、预计送达时间和异常提醒。
5. **退款/售后进度中心**：支持部分退款、退货退款、上传凭证、协商记录和进度时间轴。
6. **商品收藏和降价提醒**：用户收藏商品后，价格变化或重新上架时发送通知。
7. **评价体系升级**：支持图文评价、追评、商家回复、评价举报和评价审核。
8. **秒杀防刷与预约提醒**：支持预约、开售提醒、限购、排队、库存预占和失败补偿。
9. **运营数据看板**：增加 GMV、订单转化率、复购率、客单价、退款率、库存周转率等指标。
10. **客服会话与工单系统**：支持人工转接、会话记录、售后工单、满意度评价和客服服务时效统计。

## 三、发现的漏洞和 Bug

### 高危

#### 1. 公告内容存在存储型 XSS 风险

位置：

- `src/components/home/NoticeCarousel.vue:33`
- `src/views/login/Login.vue:55`

公告内容直接使用：

```vue
<div v-html="current.content"></div>
```

`NoticeCarousel.vue` 没有进行任何清洗。若管理员发布恶意 HTML，所有访问首页或公告的用户都可能执行恶意脚本，导致 Token、用户信息或操作权限泄露。

`Login.vue` 虽有 `sanitizeNoticeContent`，但过滤规则仍不够完整，例如仅限制 URL 形式，不限制协议、协议相对路径和危险协议变体，不能替代成熟 HTML Sanitizer。

建议：

- 服务端保存前统一过滤；
- 前端统一使用 DOMPurify 或严格白名单；
- 禁止 `script`、事件属性、危险 URL、SVG、内联样式等；
- `NoticeCarousel.vue` 不能直接输出后端富文本。

#### 2. 路由权限不能作为安全防护

位置：

- `src/router/index.js:312-333`
- `src/router/menuConfig.js:98-101`

当前权限主要依赖：

```js
if (hasToken && !canAccess(uType, to.meta.types)) {
  next(landingFor(uType));
}
```

攻击者可以修改 `localStorage` 中的 `sc_token`、`sc_user`、`sc_perms`，绕过前端页面限制或伪造用户信息。前端守卫只能防止普通误操作，不能防止接口越权。

必须确认后端所有接口都不信任前端传入的：`uId`、`uType`、`orderStatus`、`addressId`、`couponId`、订单 ID、商品 ID、商家范围参数。

#### 3. 订单 ID、地址 ID、售后 ID 存在潜在越权入口（IDOR/BOLA）

涉及位置：

- `src/views/order/OrderDetail.vue:413`
- `src/views/order/OrderPay.vue:238`
- `src/views/user/UserAddress.vue:193`
- `src/api/order.js:46-58`
- `src/api/address.js:3-31`
- `src/api/aftersale.js:4-25`

前端大量通过 URL 或参数传递资源 ID：

```js
getOrderById(id)
updateOrderStatus(orderId, -1)
getAddressList(uId)
deleteAddress(aId)
applyAfterSale({ oId })
```

如果后端没有基于当前 Token 做归属校验，用户可通过修改 ID：查看他人订单、查看/删除/修改他人地址、取消他人订单、发起他人订单售后、操作其他商家的订单。属于典型 IDOR/BOLA 风险，需重点测试。

### 中危

#### 4. Token 和用户信息保存在 localStorage

位置：

- `src/utils/auth.js:1-27`
- `src/store/index.js:9-16`

风险：任意 XSS 可读取 Token；浏览器插件或同源恶意脚本可能读取；登出、过期、多标签页同步机制不完善。建议使用 HttpOnly Cookie，或至少缩短 Token 有效期并增加 Token 轮换和设备管理。

#### 5. 密码找回第一步没有真正校验验证码

位置：`src/views/login/ForgotPassword.vue:150-157`

```js
// 这里仅做本地必填校验
this.step = 1;
```

真正校验直到最终重置密码时才调用后端。用户可直接进入第二步，交互反馈不准确；若后端重置接口校验不严，会直接形成账户接管。建议增加独立的服务端验证码验证接口，返回一次性 reset ticket，后续重置只提交 ticket。

#### 6. 验证码发送前端限流不足

位置：

- `src/views/register/Register.vue:234-253`
- `src/views/login/ForgotPassword.vue:128-147`
- `src/api/user.js:26-46`

前端 60 秒倒计时不能防止刷新页面、多标签页、直接调用接口、修改 JS 状态。后端必须增加手机号、邮箱、IP、设备、账号维度的限流、验证码错误次数限制和黑名单策略。

#### 7. 图片上传校验可被绕过

位置：

- `src/components/AfterSaleApplyDialog.vue:32-45`
- `src/components/OrderReviewDialog.vue:35`
- `src/views/product/components/ProductFormDialog.vue:44-53`
- `src/views/user/UserDetail.vue:14-23`
- `src/views/system/NoticeList.vue:102-114`

前端只检查 `file.type` 和 `file.size`。攻击者可直接请求上传接口伪造 MIME 类型或上传恶意文件。建议后端使用文件头识别真实类型、限制扩展名、随机命名、存储到不可执行目录、图片重新编码、禁用或严格清洗 SVG、校验像素数量、病毒扫描。

#### 8. 模拟支付接口存在业务滥用风险

位置：

- `src/views/pay/MockCashier.vue:104-111`
- `src/api/pay.js:28-34`

```js
simulatePay(transactionId, result)
```

如果该接口在生产环境可访问，用户可能直接提交 `SUCCESS` 伪造支付成功。建议：模拟支付仅限开发环境或管理员测试账号；后端通过环境配置关闭；生产环境删除该接口；支付成功必须由服务端网关回调确认；校验交易单归属、金额、状态和幂等性。

#### 9. 前端允许提交订单金额、价格和用户 ID

位置：

- `src/views/cart/CartList.vue:322-336`
- `src/views/product/ProductBuy.vue:249-259`

请求中包含 `uId`、`expectedPrice`、`expectedPayAmount`、`couponId`，均可被浏览器修改。它们可用于展示比对，但不能作为最终业务依据。后端必须：从 Token 获取用户身份；重新查询商品价格、促销、库存；重新计算优惠券；校验地址属于当前用户；忽略或严格校验客户端金额字段；使用事务保证库存和订单创建一致性。

#### 10. 公告富文本编辑和展示链路缺少统一清洗

位置：

- `src/views/system/NoticeList.vue:117-121`
- `src/views/system/NoticeList.vue:160-180`
- `src/components/home/NoticeCarousel.vue:33`

编辑器允许输入富文本并在多处直接展示，清洗逻辑只在登录页单独存在，安全策略不一致。建议统一封装 `sanitizeRichText(content)`，并在服务端保存和返回时均执行清洗。

#### 11. 知识库富文本输出存在潜在 XSS

位置：

- `src/views/work/KnowledgeQuick.vue:63`
- `src/views/work/KnowledgeQuick.vue:77`
- `src/views/work/KnowledgeQuick.vue:81`
- `src/views/work/KnowledgeQuick.vue:298-308`

存在多处 `v-html="current.question"` / `v-html="boldAnswer(current.answer)"`。`boldAnswer` 先解析后端 HTML，再重新生成 `innerHTML`。如果知识库内容来源包含不可信用户输入，可能触发 XSS。建议使用统一 HTML Sanitizer，且不要通过字符串拼接构造 HTML。

#### 12. `v-html` 高亮虽有转义，建议继续收敛

位置：

- `src/views/product/ProductList.vue:90`
- `src/views/product/ProductList.vue:100`
- `src/views/product/ProductList.vue:394-406`

当前高亮函数已对 `&`、`<`、`>` 做转义，暂未发现明显 XSS，但使用 `v-html` 仍扩大维护风险。建议改为渲染文本片段和 `<mark>` 节点，或保留实现并补充单元测试（覆盖商品名含 `<script>`、`&lt;`、正则特殊字符等情况）。

### 一般问题和功能 Bug

#### 13. 注册成功后跳转到 `/login` 而非对应角色登录页

位置：

- `src/views/register/Register.vue:271-274`
- `src/views/login/Login.vue:18`

`/login` 会重定向到 `/portal`，用户需要再次选择身份，体验不连贯。建议：

```js
this.$router.push(`/login/${this.registerForm.uType === 1 ? 'merchant' : 'customer'}`);
```

#### 14. 注册页和忘记密码页的 `/login` 返回路径不明确

位置：

- `src/views/register/Register.vue:46`、`:273`
- `src/views/login/ForgotPassword.vue:66`、`:178`

都跳转 `/login` 最终回到角色选择页。建议保留来源角色参数，避免用户重复选择。

#### 15. 验证码倒计时可能重复创建定时器

位置：

- `src/views/register/Register.vue:241-247`
- `src/views/login/ForgotPassword.vue:135-142`

主要依靠按钮 disabled 防重复点击，快速事件或状态异常可能造成计时器覆盖。建议发送前清理旧 timer，并用时间戳计算剩余时间，不依赖递减计数。

#### 16. 登录失败错误处理被完全静默

位置：`src/views/login/Login.vue:113-124`

`catch(() => {})` 使接口错误可能无明确提示。建议至少区分：用户名或密码错误、账号锁定、验证码/风控失败、网络异常、服务不可用。

#### 17. 订单状态转换应由后端状态机限制

位置：

- `src/views/order/MyOrderList.vue:351-365`
- `src/views/order/OrderDetail.vue:390-401`
- `src/views/order/OrderPay.vue:367-385`
- `src/api/order.js:53-58`

前端可提交任意 `orderStatus`。后端必须限制合法状态转换（待支付→已取消、已支付→已发货、已发货→已完成等），禁止已完成订单再次取消、顾客执行发货、重复确认收货。

#### 18. 订单操作缺少前端重复提交锁

位置：

- `src/views/order/MyOrderList.vue:351-365`
- `src/views/order/OrderDetail.vue:374-401`
- `src/views/order/OrderList.vue:268-281`

部分按钮有 loading，但没有按订单 ID 的统一操作锁，网络慢时可重复点击。建议前端增加按订单 ID 的操作锁，后端增加幂等和状态条件更新。

#### 19. 售后退款金额由前端展示，存在误导风险

位置：

- `src/components/AfterSaleApplyDialog.vue:15-16`
- `src/views/order/MyOrderList.vue:439-441`
- `src/views/order/OrderDetail.vue:214-215`

前端直接使用 `order.orderAmount` 作为预计退款金额，但实际退款可能受优惠券、部分退款、已退款金额、运费影响。应由后端返回可申请退款金额。

#### 20. 售后/商品图片 URL 没有校验来源

位置：

- `src/components/AfterSaleApplyDialog.vue:144-148`
- `src/views/order/OrderDetail.vue:292-296`

图片 URL 直接从上传响应和接口返回值读取。若后端返回外部地址，可能造成隐私泄露、追踪像素、外链资源替换、混合内容问题。建议只允许平台图片域名或相对路径，并对返回 URL 做白名单校验。

#### 21. `getUser()` JSON 解析缺少异常保护

位置：`src/utils/auth.js:16-19`

`localStorage.sc_user` 被改为非法 JSON 时，应用启动或路由守卫可能直接抛异常导致页面不可用。建议使用 `try/catch`，解析失败时清理缓存并返回 `null`。

#### 22. 权限缓存可能残留或被篡改

位置：

- `src/store/index.js:9-16`
- `src/store/index.js:72-75`

`sc_perms` 存于 localStorage，登出会清理，但账号切换、Token 失效、异常关闭等场景可能残留，且可被直接修改。建议权限以服务端每次会话校验为准，缓存只用于界面展示，不用于真正授权。

#### 23. 公告、知识库和商品图片存在第三方资源加载风险

位置：

- `src/components/home/NoticeCarousel.vue:63-67`
- `src/views/login/Login.vue:86`
- 多处 `el-image :src`

如果 URL 来自用户可控数据，可能加载恶意第三方资源，造成隐私泄漏或 SSRF 间接风险。建议资源域名白名单、强制 HTTPS、限制重定向。

#### 24. 依赖版本偏旧，存在供应链和漏洞管理风险

`package.json` 中：`vue ^2.6.14`、`axios ^0.24.0`、`element-ui ^2.15.13`、`@vue/cli-service ^4.5.15`、`eslint ^6.8.0`。

建议：锁定并定期审计 `package-lock.json`；执行 `npm audit`；评估 Axios、Vue 2、Vue CLI 4 的升级路径；对无法升级的组件增加 CSP、依赖补丁和安全监控。
